# Googleフォーム作成で 502 が出るとき — 別角度からの確認

**「手順書どおりにしたのにまだ 502 になる」** ときに、別の角度から原因を切り分けるためのメモです。  
（技術的な用語はなるべく少なめに、やることを番号で書きます。）

---

## 1. ブラウザのコンソールに出るメッセージについて（502 とは別です）

次のメッセージは **このアプリの不具合ではありません**。無視してかまいません。

- **「Unchecked runtime.lastError: The message port closed before a response was received」**
- **「Unchecked runtime.lastError: No tab with id: 862739405」** など（数字は毎回違うことがあります）

これらは **Chrome や Edge にインストールした拡張機能**（広告ブロック・翻訳・パスワード管理など）が原因で出ています。  
**本当に直す必要があるのは「502」だけ**です。

---

## 2. 502 とは何か（やさしく言うと）

- あなたが「Googleフォームを作成」ボタンを押す  
  → アプリ（Railway）が **Google 側の「GAS」というプログラム** に「フォームを作って」とお願いする  
  → GAS が **「結果」を決まった形式（JSON）で返す** と、アプリはフォームURLを表示する  
  → GAS が **エラーになったときに「エラーのページ（HTML）」を返してしまう** と、アプリは「何かおかしい」と判断して **502** を出します。

つまり **502 = 「GAS がエラーのときに、決まった形式で返せていない」** 状態です。  
ログにも **「GAS response not JSON … body=<!DOCTYPE html」** と出ており、「GAS が HTML を返した」ことが原因です。

---

## 3. 別角度の確認（この順でやってみてください）

### 3-0. 【最も多い原因】ウェブアプリの URL をブラウザで開いて「許可」したか

- GAS を「誰でも使えるウェブアプリ」としてデプロイしたあと、**その URL を一度もブラウザで開いていない**と、**初回アクセス時に Google が「このアプリへのアクセスを許可しますか？」という HTML ページを返します**。アプリ（Railway）から呼ぶとその HTML が返り、502 になります。
- **やること**: 「デプロイを管理」に表示されている **ウェブアプリの URL** をコピーする。  
  **URL に `/macros/u/1/s/` が含まれている場合、ブラウザで開くと「ファイルを開くことができません」になることがあります。** その場合は **「3-0 の別のやり方」**（エディタから認証）を試してください。  
  うまく開ける場合は「このアプリへのアクセスを許可しますか？」と出たら **「許可」** をクリックする。Railway の GAS_WEB_APP_URL には **`/macros/s/…/exec`** の形式（`u/1` なし）を設定する。

**3-0 の別のやり方（URL を開くと u/1 がついて「ファイルを開くことができません」になる場合）**  
1. script.google.com でプロジェクトを開く。  
2. メニュー **「実行」** → **「関数を実行」** → **「authorizeApp」** を選んで実行する。  
3. **「承認が必要です」** と出たら **「許可」** を選び、表示に従ってアクセスを許可する。  
4. これで Drive 等の認証が完了する。あらためてアプリから「Googleフォームを作成」を試す。  
（Code.gs に `authorizeApp` 関数が無い場合は、リポジトリの最新の CreateGoogleFormFromQuestionText.js を貼り替えて「新バージョン」でデプロイしてから上記を実行する。）

### 3-1. GAS の「デプロイ」が本当に「新バージョン」か

- **「Code.gs を貼り替えて保存した」だけでは、外の世界に反映されません。**  
  「デプロイ」で **「新バージョン」を選んで「デプロイ」ボタンを押す** までしないと、アプリが呼び出すのは **前の古いプログラム** のままです。
- **確認**: script.google.com で、**「デプロイ」→「デプロイを管理」** を開く。  
  **「バージョン」** が **「新バージョン」** になっているデプロイを選び直して、もう一度 **「デプロイ」** を実行したあと、もう一度アプリで「Googleフォームを作成」を試す。

### 3-2. Railway が呼んでいる URL が、いまデプロイした GAS か

- アプリ（Railway）は **環境変数「GAS_WEB_APP_URL」** に書かれた URL にだけアクセスします。  
  別のプロジェクトや、昔のデプロイの URL が入っていると、**そちら（古い GAS）** が動いて 502 になることがあります。
- **確認**:  
  - GAS の「デプロイを管理」で、**いま使いたい「ウェブアプリ」の URL**（`https://script.google.com/macros/s/…/exec`）をコピーする。  
  - Railway の **Variables** で **GAS_WEB_APP_URL** の **値** が、その URL と **完全に同じ** か確認する。  
  違っていたら、Railway の値を正しい URL に貼り替えて保存し、必要なら再デプロイする。

### 3-3. GAS の「実行」ログでエラー内容を見る（ここが重要）

- GAS は **「いつ・何回・成功したか／失敗したか」** を記録しています。  
  ここを見ると **「なぜ HTML が返ったか」** の手がかりが分かります。
- **やり方**:  
  1. https://script.google.com/ を開き、**フォーム作成用のプロジェクト** を開く。  
  2. 左メニューで **「実行数」**（または「Executions」）をクリックする。  
  3. 一覧から **「失敗」** や **「エラー」** になっている実行を探す（「Googleフォームを作成」を押した時刻に近いもの）。  
  4. その行をクリックして **「エラーメッセージ」** を開く。  
  5. 出てきた **エラー文** をそのままコピーする（またはスクリーンショットを撮る）。

**この「エラー文」を教えてもらえると、原因をかなり絞り込めます。**  
（例: 「DriveApp.getFileById の権限がない」「〇〇 は null です」など）

### 3-4. Code.gs の「先頭付近」がリポジトリと同じか

- まれに **「貼り替えたつもりが、古いコードが残っている」「別のファイルが開いていた」** ということがあります。  
  そのため、**GAS の Code.gs のいちばん上から 20 行くらい** が、このリポジトリの **CreateGoogleFormFromQuestionText.js** の冒頭（`/**` や `function doPost` がすぐ出てくる部分）と **同じか** を目視で確認すると安心です。  
  特に **「function doPost(e)」** と **「try { … } catch」** が含まれているかを見てください。

---

## 4. 教えてもらえると助かる情報（任意です）

原因をさらに特定しやすくするため、次のどれか（できる範囲で）を教えてください。

1. **GAS の「実行数」で、失敗した実行を開いたときのエラーメッセージ**（コピー＆ペーストまたはスクリーンショット）  
2. **「デプロイを管理」で「新バージョン」を選んでデプロイしたあと、もう一度フォーム作成を試したか**（試した / まだ試していない）  
3. **Railway の GAS_WEB_APP_URL の値が、GAS の「デプロイを管理」に表示されているウェブアプリの URL と一致しているか**（一致している / 違う / 確認していない）

---

## 5. まとめ

- **ブラウザの runtime.lastError / No tab with id** → 拡張機能が原因。無視してよい。  
- **502** → GAS がエラー時に HTML を返している。  
- **やること**: (1) GAS を「新バージョン」で必ずデプロイし直す (2) Railway の URL と GAS の URL が同じか確認する (3) GAS の「実行数」で失敗時のエラー文を確認する。  
- **エラー文** を共有してもらえれば、次の対策を具体的に提案できます。
