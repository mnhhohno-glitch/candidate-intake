# 仕様確認と改善メモ

## 実施した改善（Excelの質・体感速度）

### 1. ①共通解析プロンプト（01）の強化
- **課題**: filemaker_mapping に十分なキーが入らず、後段で空白が多くなっていた。
- **対応**:
  - filemaker_mapping は「入力に一言でも触れている項目を漏れなく格納」と明記。
  - 基本情報シートの列名を列挙し、該当する記述があれば必ずキーとして追加するよう手順を追加。
  - work_history も「可能な限り含める」とし、省略を減らす指示に変更。

### 2. ③FileMaker用Excelプロンプト（03）の強化
- **課題**: 「曖昧なら null」が強く、filemaker_mapping に既にある値も出力されないことがあった。
- **対応**:
  - **fill_rules** を追加: filemaker_mapping に存在するキーはすべて対応する列に出力すること、null にしてよいのは根拠が無い列と missing_items のみと明記。
  - final_instruction に「filemaker_mapping に存在するキーは省略して null にしない」を追加。

### 3. サーバー側バックフィル（実装）
- **課題**: Geminiが一部列を null のまま返しても、共通解析には値がある場合がある。
- **対応**:
  - `excelBackfill.ts` を追加。
  - **applyFilemakerBackfill**: 基本情報シートの各行について、列が空でも filemaker_mapping に値があればその値をセルに反映。
  - **applyWorkHistoryBackfill**: 職歴情報シートの各行に、extracted_facts.work_history の企業名・在籍期間・職種・退職理由等を補完。
  - Excel API で Gemini 取得後に上記2つを実行してから xlsx を生成するよう変更。

### 4. 処理時間の可視化
- **課題**: 「出力が早すぎてAIが動いていないように感じる」（例: 約10秒で完了、GPTでは3〜5分かかっていた）。
- **対応**:
  - 各APIで「Calling Gemini...」と「Gemini done in Xms」をコンソールに出力。
  - **共通解析（01）**では、送信前に入力文字数をログ出力: `Input lengths: PDF=○ chars, interview=○ chars, flagList=○ chars`。PDF・面談メモが極端に短い場合はテキスト抽出の不具合を疑う。
  - 共通解析の maxOutputTokens を 16384、デフォルトを 32768 に増やし、長い filemaker_mapping が途中で切れないようにした。プロンプトで「3資料をすべて読み・確認用ステップ」を必須にしたため、応答に時間がかかる場合がある。

### 5. Gemini パラメータ
- temperature を 0.3 → 0.2 に変更（ぶれをやや抑制）。
- maxOutputTokens を 8192 → 16384 に変更（長い行・多数列でも切れにくくする）。

## インポートExcelプロンプト正本（応募書類ヒアリングとは別）

- **正本YAML**: `specs/インポートExcelプロンプト_正本.yaml`
- 求職者へ応募書類を作るヒアリング用プロンプトとは別です。本アプリは「インポートExcelファイルを作る」用途です。
- 実装との対応:
  - **Web履歴書PDFファイル名**: 「5から始まる7桁」を含まないと処理を開始せず、エラーメッセージで再アップロードを要求。
  - **求職者NO**: PDFの**ファイル名**からのみ抽出。面談メモ・PDF本文の番号は使用しない。APIでファイル名検証後に抽出し、共通解析結果に上書き注入。
  - **フラグリスト**: シート名「リスト」があればそれを優先して読み取り。職種フラグは職種リスト、退職理由はカテゴリ_大・中・小から選択。
  - **出力ファイル名**: 基本情報シート_氏名.xlsx（1ファイルに2シートを含む）。

## 仕様フロー（確認用）

1. **アップロード** → PDF / 面談ログ .txt / フラグリスト .xlsx のいずれか以上
2. **① 共通解析** → 01 プロンプトで Gemini 呼び出し。extracted_facts / filemaker_mapping / missing_items を生成。
3. **② 質問JSON** → 02 プロンプトで common_analysis_json のみを入力に質問定義を生成。
4. **③ Excel** → 03 プロンプトで common_analysis_json のみを入力に excel_files JSON を生成 → **バックフィル適用** → .xlsx 作成 → ダウンロード。

共通解析で filemaker_mapping に多く詰めるほど、バックフィルと合わせてExcelの空白は減ります。
