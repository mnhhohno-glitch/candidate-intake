# 候補者情報取り込みアプリ（Candidate Intake）— 現行仕様書

本ドキュメントは、**Googleフォーム作成の追加機能**の要件定義を行うために、現在のアプリの仕様を整理したものです。GPT等へ共有し、新規要件の検討に利用してください。

---

## 1. アプリの目的とスコープ

### 1.1 目的
- **転職支援会社**の業務において、**新規求職者**の情報を以下の3種類の入力から取り込み、**共通の整理データ**と**FileMaker用Excel**を一気通貫で生成する。
- あわせて、**応募先職種に応じた「候補者へ送る質問文」**（テキスト）を生成し、コピーしてメール等で送付できるようにする。
- **Googleフォーム用の質問定義JSON**は生成するが、**実際のGoogleフォームの作成・編集・公開**は現状では行っていない（JSONのみ出力し、プレビュー編集可能）。

### 1.2 スコープ（現状）
- **入力**: 履歴書PDF、面談メモ（.txt）、フラグリスト（.xlsx）のいずれか1つ以上。
- **出力**:
  - 共通解析JSON（common_analysis_json）
  - Googleフォーム質問定義JSON（form_metadata + questions）— **フォームの実体は作らない**
  - FileMaker用Excel（.xlsx）：基本情報シート・職歴情報シートの2シート
  - 候補者向け質問文（プレーンテキスト）：職種・実績カテゴリ指定で生成、コピー用

### 1.3 スコープ外（現状）
- Googleフォームの**実際の作成・編集・公開・回答収集**。
- 認証・権限管理（誰がどの求職者を編集できるか等）。
- 履歴書・面談メモのバージョン管理。

---

## 2. ユーザーと利用シーン

### 2.1 ユーザー
- **キャリアアドバイザー（CA）** 等、転職支援の現場担当者。技術的な前提知識は不要な運用を想定。

### 2.2 主な利用シーン
1. **新規求職者登録**: 求職者番号（5から始まる7桁）・氏名・担当CAを登録。
2. **初回面談後の取り込み**: 履歴書PDF・面談メモ・フラグリストをアップロードし、「実行」で共通解析 → 質問JSON → Excel を順に生成。Excelをダウンロードし、FileMakerへインポート。
3. **求職者詳細画面**: 既存求職者の再実行（ファイル差し替え・再解析）、**質問文生成**（職種・実績カテゴリを指定して候補者向け質問文を生成しコピー）、Excel再出力（キャッシュから取得）。
4. **一覧での操作**: 求職者一覧の検索、選択したレコードの一括削除、個別削除・再出力。

## 3. システム構成

### 3.1 技術スタック
- **フレームワーク**: Next.js（App Router）
- **言語**: TypeScript
- **AI**: Google Gemini API（テキスト・画像・PDF入力に対応）
- **保存**: ファイルシステム（`data/records.json`、`data/cache/{candidateId}_last.xlsx`）。環境変数 `DATA_DIR` で保存先を変更可能。Railway 等では Volume マウントを推奨。

### 3.2 フォルダ構成（抜粋）
```
candidate-intake/
├── specs/                    # プロンプト仕様（YAML）
│   ├── 01_common_analysis_prompt.yaml      # 共通解析
│   ├── 02_google_form_prompt.yaml          # 質問定義JSON
│   ├── 03_filemaker_excel_prompt.yaml      # Excel用データ
│   ├── 04_hearing_question_text_prompt.yaml # 質問文（テキスト）
│   ├── 05_structured_extract_prompt.yaml   # 質問文用・構造化抽出
│   └── 06_achievement_category_followup.yaml # 実績ヒアリング
├── src/
│   ├── app/
│   │   ├── page.tsx                        # トップ（求職者一覧）
│   │   ├── register/page.tsx              # 新規求職者登録＋パイプライン実行
│   │   ├── records/[candidateId]/page.tsx # 求職者詳細（再実行・質問文生成・Excel）
│   │   └── api/
│   │       ├── records/                    # 求職者CRUD・一括削除
│   │       ├── records/[candidateId]/      # 1件取得・更新・削除・キャッシュ・Excel再出力
│   │       └── intake/                     # 解析・質問・Excel・質問文
│   ├── components/                         # UploadPanel, ResultPanel, RecordRegister 等
│   ├── lib/recordsStore.ts                 # レコード・キャッシュ永続化
│   ├── services/                           # Gemini呼び出し・Excel生成・loadSpec 等
│   └── types/                              # commonAnalysis, googleForm, excelExport 等
└── docs/
```

### 3.3 環境変数
| 変数名 | 説明 | 必須 |
|--------|------|------|
| `GEMINI_API_KEY` | Google Gemini API キー | はい |
| `DATA_DIR` | データ保存先ディレクトリ（未指定時は `data/`） | いいえ |
| `HEARING_GATE_MIN_CHARS` | 質問文生成ゲート：PDF抽出テキストの最小文字数（0でなければ通過。厳格化時は例: 101） | いいえ |
| `HEARING_GATE_QUALIFICATION_SUBSTRINGS` | 質問文ゲート：資格キーワード（カンマ区切り。未設定ならスキップ） | いいえ |
| `HEARING_GATE_ADDRESS_SUBSTRINGS` | 質問文ゲート：住所キーワード（同上） | いいえ |

## 4. データモデル

### 4.1 求職者レコード（StoredRecord）
- **保存先**: `data/records.json` の `records` 配列。
- **項目**:
  - `candidateId`: 求職者番号（5から始まる7桁。一意）
  - `candidateName`: 氏名
  - `careerAdvisor`: 担当キャリアアドバイザー
  - `createdAt`: 作成日時（ISO8601）
  - `lastOutputAt`: 最終出力日時（任意）
  - `attachmentSummary`: 最終実行時の添付情報（`pdfName`, `interviewLogName`, `flagListName`）

### 4.2 共通解析JSON（CommonAnalysisJson）
- **生成元**: `specs/01_common_analysis_prompt.yaml` に基づく Gemini 呼び出し。
- **入力**: 面談メモテキスト、PDF抽出テキスト、フラグリスト（シート「リスト」）の3ブロック。
- **主な構造**:
  - `extracted_facts`: 氏名・求職者NO・職歴（work_history 配列）等
  - `filemaker_mapping`: 基本情報シートの列名をキーとした値のマップ（列名は仕様と完全一致必須）
  - `missing_items`: 3資料のいずれにも記載がなく、後続で取得予定の項目名の配列
- **求職者NO**: API側でPDFファイル名から抽出（5から始まる7桁）し、共通解析結果に上書き。ファイル名に含まれない場合はエラーになる仕様。

### 4.3 Googleフォーム質問定義（GoogleFormDefinition）
- **生成元**: `specs/02_google_form_prompt.yaml`。入力は **common_analysis_json のみ**。
- **構造**:
  - `form_metadata`: `title`, `description`（任意）
  - `questions`: 配列。各要素は `id`, `title`, `required`, `type`（text / multiple_choice / checkbox / date / number 等）, `options`（選択式の場合）
- **用途**: 画面でプレビュー・編集可能。**実際のGoogleフォームの作成・更新は行っていない**。

### 4.4 Excel出力
- **生成元**: `specs/03_filemaker_excel_prompt.yaml` で `excel_files` JSON を取得し、`excelBuilder` で .xlsx に変換。共通解析の `filemaker_mapping` と `extracted_facts.work_history` をバックフィル（excelBackfill）で補完。
- **成果物**: 1ファイルに「基本情報シート」「職歴情報シート」の2シート。ファイル名は「FileMaker用_氏名.xlsx」等。
- **キャッシュ**: 実行完了時に `data/cache/{candidateId}_last.xlsx` に保存。再出力APIで取得可能。

### 4.5 質問文（候補者向けテキスト）
- **生成元**: `specs/04_hearing_question_text_prompt.yaml`。Step A（`05_structured_extract_prompt.yaml` で PDF/面談メモから構造化抽出）→ Step B（04 で質問文テキスト生成）。
- **入力**: job_type（応募先職種）、achievement_category（実績ヒアリングの職種カテゴリ）、PDF、面談メモ（任意）。
- **出力**: 候補者に送る質問本文のみ（見出し・内部メモ・URLは含めない）。自己検査（高校ブロック必須・資格ブロック必須・戸建て禁止等）と再試行あり。
- **保存**: サーバーには保存せず、画面で表示・コピーのみ。

## 5. API仕様

### 5.1 求職者（records）

| メソッド | パス | 説明 |
|----------|------|------|
| GET | `/api/records` | 全レコード一覧取得。`{ records: StoredRecord[] }` |
| POST | `/api/records` | 新規登録または上書き。Body: `{ candidateId, candidateName, careerAdvisor }` |

### 5.2 求職者1件（records/[candidateId]）

| メソッド | パス | 説明 |
|----------|------|------|
| GET | `/api/records/:candidateId` | 1件取得。404 は未登録。 |
| PATCH | `/api/records/:candidateId` | 更新。Body: `{ candidateName?, careerAdvisor? }` |
| DELETE | `/api/records/:candidateId` | 削除。キャッシュExcelも削除。 |

### 5.3 一括削除・キャッシュ・Excel再出力

| メソッド | パス | 説明 |
|----------|------|------|
| POST | `/api/records/bulk-delete` | Body: `{ candidateIds: string[] }`。指定IDを一括削除。 |
| POST | `/api/records/:candidateId/cache` | FormData: `attachmentSummary`(JSON), `excel`(File)。最終出力情報とExcelをキャッシュ。 |
| GET | `/api/records/:candidateId/excel` | キャッシュされたExcelをダウンロード。404 はキャッシュなし。 |

### 5.4 取り込みパイプライン（intake）

| メソッド | パス | 説明 |
|----------|------|------|
| POST | `/api/intake/analyze` | FormData: `candidateId`, `pdf?`, `interviewLog?`, `flagList?`。共通解析を実行し common_analysis_json を返す。求職者NOはPDFファイル名から抽出し必須。 |
| POST | `/api/intake/questions` | Body: `{ common_analysis_json }`。Googleフォーム質問定義JSONを返す。 |
| POST | `/api/intake/excel` | Body: `{ common_analysis_json }`。FileMaker用Excelをバイナリで返す（Content-Disposition でファイル名付き）。 |
| POST | `/api/intake/hearing-question-text` | FormData: `job_type`, `achievement_category`, `pdf`, `interviewLog?`, `candidate_name?`。候補者向け質問文テキストを返す。`candidate_question_text_only`。422 はゲート不合格（PDF抽出文字数不足等）。 |

## 6. 画面フローと機能

### 6.1 トップ（/）
- 求職者一覧（求職者ID・氏名・担当CA・添付・出力済み有無・操作）。
- 検索（求職者ID・氏名・担当CA）。
- 「＋ 新規求職者登録」→ `/register`。
- 行クリックで `/records/[candidateId]` へ。
- チェックボックスで選択 → 「選択した N 件を一括削除」。
- 各行的「再出力」：キャッシュExcelを取得してダウンロード。「削除」：1件削除。

### 6.2 新規求職者登録（/register）
- **ステップ1**: 求職者番号（5始まり7桁）・氏名・担当CAを入力して「登録」。成功するとレコードが確定。
- **ステップ2**: PDF・面談ログ・フラグリストをアップロードし「実行」。
  - ① 共通解析（/api/intake/analyze）
  - ② 質問JSON（/api/intake/questions）
  - ③ Excel（/api/intake/excel）
  - 完了後、キャッシュAPIで保存。結果パネルで質問リスト編集・Excelダウンロード可能。

### 6.3 求職者詳細（/records/[candidateId]）
- 氏名・担当CAの表示・編集・保存（PATCH）。
- ファイルアップロード（PDF・面談・フラグ）と「出力開始」で上記と同じ ①→②→③ を再実行。Excelダウンロード・キャッシュ保存。
- **質問文生成**:
  - 「応募先の職種」（job_type）と「実績ヒアリングの職種カテゴリ」を入力・選択。
  - 「質問文を生成」で `/api/intake/hearing-question-text` を呼び出し、生成されたテキストを表示。「コピー」でクリップボードにコピー。
- 「再出力」でキャッシュExcelをダウンロード。

## 7. プロンプト仕様（specs）概要

- **01 共通解析**: 3資料をすべて読み、extracted_facts / filemaker_mapping / missing_items を出力。filemaker_mapping のキーは基本情報シートの列名と完全一致。
- **02 Googleフォーム**: common_analysis_json のみを入力に、missing_items 等を補う質問定義JSONを生成。実際のフォーム作成はしない。
- **03 FileMaker用Excel**: common_analysis_json から excel_files（基本情報・職歴情報シート）を生成。バックフィルで filemaker_mapping と work_history を反映。
- **04 質問文（テキスト）**: job_type・achievement_category・PDF・面談メモを入力に、候補者に送る質問本文を生成。事前に Step A（05）で構造化抽出（highest_education_category, qualifications_list, 住所フラグ等）を行い、高校・資格・住所のルールを適用。自己検査と再試行あり。
- **05 構造化抽出**: 質問文生成用。PDF/面談メモから highest_education_category, qualifications_list, address_* 等をJSONで抽出。推測禁止。
- **06 実績ヒアリング**: achievement_category に応じた追加質問ブロックを04に組み込む。

## 8. ビジネスルール・制約

- **求職者番号**: 5から始まる7桁。PDFファイル名から抽出する場合は、ファイル名にその形式が含まれる必要がある。含まれない場合はエラー。
- **フラグリスト**: シート名「リスト」を優先して読み取り。フラグ列の値はリストに記載の選択肢と一致させる。
- **共通解析**: 3資料のいずれかに「一言でも」記載がある項目は filemaker_mapping に含める。省略してよいのは3つすべてに記載が無い列のみ。
- **質問文生成**: 最終学歴が「高校」以外の場合は必ず高校名・卒業年度・入学年度の確認ブロックを出力。資格が1件以上ある場合は取得年月確認ブロックを出力。住所で番地・部屋番号がある場合は「戸建てでよろしいですか」は使用禁止（建物名の記載をお願いする文言を使用）。
- **ゲート**: 質問文生成で、PDF抽出テキストが一定文字数未満の場合は 422 を返し、Step A/B は実行しない（コスト・品質のため）。

## 9. 今後の拡張（Googleフォーム作成）に向けた整理

- **現状**: 質問定義は **JSON**（form_metadata + questions）として生成・編集可能。**Googleフォームの実体（作成・編集・公開・回答収集）は未実装**。
- **追加機能の検討に必要な観点**:
  - どのタイミングでフォームを作成するか（新規登録後・詳細画面の「実行」後・質問文生成後・別ボタン等）。
  - Google Forms API（または Apps Script）との連携方法、認証（サービスアカウント・OAuth）。
  - 1求職者1フォームか、テンプレート＋候補者ごとのコピーか。
  - フォームの編集・再生成・URLの保存・候補者への送付フローとの統合。
  - 既存の「質問定義JSON」と「実際のフォーム」の対応（JSONからフォーム項目を自動生成するか、手動編集をどう扱うか）。

本仕様書をGPT等に渡し、「上記の現行仕様を前提に、Googleフォームの作成機能の要件定義をしてほしい」と依頼することで、追加機能の要件を整理できます。
