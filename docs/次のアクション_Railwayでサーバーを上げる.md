# 次のアクション — Railway でサーバーを上げる（ターミナルは使いません）

**ターミナル（黒い画面）は一切使いません。** ここに書いてあるのは、すべて「ブラウザでサイトを開いて、ボタンを押す・文字を入力する」操作だけです。番号の順にやっていけば完了します。

---

## やること一覧

| 番号 | やること | かかる時間の目安 |
|------|----------|------------------|
| 1 | Railway に GitHub でログインする | 約1分 |
| 2 | 新しいプロジェクトを作り、GitHub の「candidate-intake」を選んでデプロイする | 約1分（デプロイ自体は数分かかります） |
| 3 | 環境変数「GEMINI_API_KEY」を1つだけ追加する | 約2分 |
| 4 | 公開用のURL（ドメイン）を1つ発行する | 約1分 |
| 5 | そのURLをブラウザで開いて、画面が表示されるか確認する | 約30秒 |

---

## 1. Railway にログインする

1. **ブラウザ**（Chrome や Edge など）を開く。
2. アドレス欄に **`https://railway.app`** と入力して Enter を押す。
3. 画面に **「Login」** または **「Log in」** というボタンがあれば、それを**クリック**する。
4. **「Login with GitHub」** または **「Sign in with GitHub」** と書いてあるところを**クリック**する。
5. GitHub の画面に切り替わったら、すでに GitHub にログインしていれば **「Authorize railway」** のような**緑のボタン**をクリックする。  
   - ログインしていない場合は、GitHub のユーザー名とパスワードを入力してから、同じく「Authorize」をクリックする。
6. Railway の画面に戻り、**プロジェクト一覧**や **「New Project」** のようなボタンが見えれば、ログイン完了です。

---

## 2. GitHub の「candidate-intake」をデプロイする

1. Railway の画面で **「New Project」** というボタンを**クリック**する。
2. 次のような選択肢が出ます：
   - **「Deploy from GitHub repo」** または **「Deploy from GitHub」**  
   → これを**クリック**する。  
   （「Empty Project」や「Deploy from Template」は選ばない。）
3. **「Configure GitHub App」** や **「Install GitHub App」** と出た場合：  
   - **「Install」** や **「Configure」** をクリックする。  
   - 表示された GitHub の画面で、**「Only select repositories」** を選び、一覧から **「candidate-intake」** にチェックを入れる。  
   - **「Install」** または **「Save」** をクリックする。  
   - Railway の画面に戻る。
4. リポジトリの一覧が表示されるので、**「candidate-intake」** の行を**クリック**して選ぶ。  
   （「mnhhohno-glitch / candidate-intake」のように表示されていることがあります。）
5. **「Deploy Now」** や **「Add to project」** など、デプロイを始めるボタンを**クリック**する。
6. 画面に **「Building」** や **「Deploying」** のような表示が出て、ログが流れ始めます。**2〜5分ほど待つ**と、**「Success」** や **「Active」** のような表示に変わる場合があります。  
   - ここでは「デプロイが始まった」ことが分かれば十分です。次に進んで大丈夫です。

---

## 3. 環境変数「GEMINI_API_KEY」を追加する

アプリが AI（Gemini）を使うために、**API キー**を Railway に登録します。

### 3-1. API キーを手元でコピーする（Cursor で）

1. **Cursor** を開き、このプロジェクトのフォルダ（`candidate-intake`）を開いた状態にする。
2. 左のファイル一覧で **「.env.local」** というファイルを**クリック**して開く。  
   - 一覧に表示されない場合は、**「エクスプローラー」** の検索欄に **`.env.local`** と入力してファイルを探す。
3. 中身は次のような1行になっています：  
   **`GEMINI_API_KEY=AIzaSy...`**（`=` の後ろが長い文字列）
4. **`=` の後ろの部分だけ**をマウスで選択し、**右クリック** → **「コピー」** でコピーする。  
   - または、`AIzaSy` から末尾まで全体を選択してコピーしてもかまいません（`GEMINI_API_KEY=` は含めなくてOK。Railway では「名前」と「値」を別々に入力するため）。

### 3-2. Railway の画面で変数を追加する

1. **Railway の画面**（ブラウザ）に戻る。
2. 今デプロイした **「candidate-intake」** の**サービス（四角やカードで表示されているもの）** を**クリック**する。
3. 上や横にあるタブやメニューから **「Variables」** という文字を**クリック**する。  
   - 英語では **「Variables」**、日本語表示なら **「変数」** のような名前です。
4. **「+ New Variable」** または **「Add Variable」** または **「RAW Editor」** のようなボタンを**クリック**する。
5. **名前（Name / Key）** の欄に、次の文字を**そのまま**入力する（コピー＆ペーストでOK）：  
   **`GEMINI_API_KEY`**
6. **値（Value）** の欄に、**3-1 でコピーした API キー**（`AIzaSy...` で始まる長い文字列）を**貼り付け**する。
7. **「Add」** や **「Save」** をクリックして保存する。  
   - 保存すると、多くの場合 **自動で再デプロイ**が始まります。始まらなくても、次の「4」に進んで大丈夫です。

---

## 4. 公開用のURL（ドメイン）を発行する

1. 同じ **「candidate-intake」** のサービスが開いている状態で、**「Settings」** または **「Deployments」** のタブを**クリック**する。
2. 画面を下にスクロールし、**「Networking」** や **「Public Networking」** や **「Domains」** という見出しを探す。
3. **「Generate Domain」** または **「Add Domain」** というボタンを**クリック**する。  
   - 初回は「Generate Domain」を押すと、自動で **「〇〇〇.up.railway.app」** のようなアドレスが1つ作られます。
4. 表示された **URL（〇〇〇.up.railway.app）** を**コピー**する。  
   - 多くの場合、URL の横に **コピー用のアイコン**があるので、それをクリックするとコピーできます。  
   - または、URL をマウスで選択して右クリック → **「コピー」** でもOKです。

---

## 5. ブラウザで開いて確認する

1. ブラウザの**アドレス欄**をクリックし、**4 でコピーした URL** を**貼り付け**て Enter を押す。  
   - 必ず **`https://`** が付いた形で開く（例：`https://candidate-intake-production.up.railway.app`）。
2. **「候補者情報取り込み」「Candidate Intake」** のようなタイトルの画面が表示され、  
   「担当キャリアアドバイザー」や「ファイルをアップロード」などの項目が見えれば **成功** です。
3. もし **「GEMINI_API_KEY is not configured」** のようなエラーが出た場合は、**「3. 環境変数」** に戻り、  
   - 変数名が **`GEMINI_API_KEY`** と完全に一致しているか  
   - 値に余分なスペースや改行が入っていないか  
   を確認し、保存し直したあと、**「Redeploy」** や **「Deploy」** を一度クリックしてから、もう一度 URL を開いてみてください。

## 6. データを保持する（プッシュ・再デプロイしても消えないようにする）

**デフォルトでは、求職者一覧や再出力用のキャッシュは「そのサーバーの中」にだけ保存されます。** 再デプロイ（Git プッシュや「Redeploy」）するとサーバーが作り直されるため、**データは消えます**。

**データを残したい場合**は、Railway の **Volume（ボリューム）** を使います。

1. Railway のプロジェクトで、デプロイした**サービス**をクリックする。
2. **「Variables」** のとなりなどにある **「Volumes」** または **「Storage」** を開く。
3. **「Add Volume」** や **「Create Volume」** をクリックする。
4. **Mount Path（マウントパス）** に **`/data`** と入力する（このパスにデータが保存されます）。
5. 保存する。
6. **「Variables」** に戻り、**「+ New Variable」** で次の変数を追加する。
   - **Name**: `DATA_DIR`
   - **Value**: `/data`
7. 保存すると再デプロイが走る。**以降は、求職者一覧と再出力用キャッシュが Volume に保存され、プッシュや再デプロイ後も残ります。**

※ Volume を追加する前に登録したデータは消えたままです。Volume 設定後から保存されたデータだけが残ります。
