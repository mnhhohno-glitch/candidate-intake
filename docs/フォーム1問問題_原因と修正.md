# フォームが1問しか出ない問題：原因と修正

## 根本原因（ログから確定した事実）

- **API（hearing-question-text）は正しく複数ブロックを返している**
  - 最新ログ: `outputBlocks= 4`, `outputChars= 890` → 4ブロック分の質問文が返っている。
- **フォームが1問になる原因は GAS 側の設計ミス**
  - API は `wrapped = 挨拶文 + "\n\n" + 質問1\n回答：\n質問2\n回答：\n..."` を返す。
  - GAS は `\n回答[：:]\n?` で分割し、**blocks[0] を「ヘッダー（説明のみ）」として addSectionHeaderItem に渡していた。**
  - 実際の blocks[0] は **「挨拶文＋第1質問（例：高校）」が連結した文字列**。
  - そのため **第1質問がフォーム項目にならず、見出しとして表示されていた**。
  - 結果: 4ブロック返ってもフォーム項目は 3 個、2ブロック返れば 1 個、1ブロックなら 0 個になる挙動だった。

## 実施した修正

### 1. GAS（CreateGoogleFormFromQuestionText.js）

- **挨拶と第1質問の分離**
  - 定数 `INTRO_END_MARKER = "ご記入頂けますと幸いです。"` を追加。
  - `splitIntroAndFirstQuestion(blocks[0])` で blocks[0] を「挨拶」と「第1質問」に分割。
  - 挨拶のみを `addSectionHeaderItem` に渡し、**第1質問は questionBlocks に含めて他の質問と同様にフォーム項目として追加。**
- **フッター除去**
  - 定数 `FOOTER_START_MARKER = "以上となります。"` を追加。
  - 最終ブロックに API 付与のフッターが含まれていたら `stripFooterFromLastBlock` で除去。
- **フォーム項目のループ**
  - 従来: `blocks[0]` は見出しのみ、`blocks[1]` 以降をループでフォーム項目にしていた。
  - 修正後: `questionBlocks = [第1質問, blocks[1], blocks[2], ...]` を 0 からループし、**全質問がフォーム項目になる。**

### 2. Next.js API（create-google-form/route.ts）

- **GAS 送信前のログ**
  - `questionTextChars` と `questionBlocks`（`\n回答[：:]\n?` で数えたブロック数）をログ出力。
  - ログで「送っている質問文の長さ・ブロック数」を確認可能にした。

## デプロイ後の確認

1. **Next.js**  
   - 修正をデプロイ後、同じ候補者で「質問文を生成」→「Googleフォームを作成」を実行。
2. **GAS**  
   - **必ず「デプロイを管理」→「新バージョン」で再デプロイする。**  
   - 同じ URL のままでコードだけ差し替わる。
3. **ログ確認**
   - `[hearing-question-text] step_b done ... outputBlocks= N`
   - `[create-google-form] sending to GAS ... questionTextChars= X questionBlocks= N`
   - フォームの質問数が N 個（挨拶＋全質問）になっているか確認。

## まとめ

- **原因**: GAS が blocks[0]（挨拶＋第1質問）を「見出しのみ」として扱い、第1質問をフォーム項目にしていなかった。
- **対応**: blocks[0] から挨拶と第1質問を分離し、第1質問も含めた全ブロックをフォーム項目として追加するよう GAS を修正した。
- **GAS を再デプロイしないと修正は反映されない。**
